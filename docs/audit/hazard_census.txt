--- READ-MODIFY-WRITE ON A WRITE-ONLY I/O LATCH — 1 site
    the game assumes: a read of 0xC40001 returns 0xFF.
                      jts16b_cabinet.v:199-202 — for A[13:12]==0 the case
                      arm only LATCHES flip and video_en from cpu_dout and
                      never assigns cab_dout, so the read takes the 8'hff
                      default at :189. The bclr therefore writes 0xBF:
                      flip off, video ON. It only looks harmless.
    on 32X:           the substitute MUST return 0xFF for this read. Anything
                      else and the write half puts an arbitrary byte in the
                      video latch. Every other site writes the shadow at
                      0xFFF018 instead; these bypass it.
    0xC40001  0x1AFF2
